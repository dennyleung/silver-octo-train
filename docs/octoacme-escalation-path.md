# OctoAcme Escalation Path Quick Reference

Use this guide when a blocker, risk, or decision cannot be resolved at the current level. Escalating promptly — and to the right person — keeps delivery on track and prevents small problems from becoming project-threatening issues.

---

## When to Escalate

Escalate when:
- A blocker cannot be resolved within **one sprint** (or within **24 hours** for critical issues).
- A decision requires authority or budget beyond the current role's mandate.
- A risk has a **High** likelihood or impact that is not being mitigated.
- A stakeholder conflict is preventing progress.
- The team is at risk of missing a committed milestone.

---

## Escalation Levels

### Level 1 — Team / Delivery
**Who escalates:** Developer, Quality Lead
**Escalate to:** Agile Coach / Scrum Master
**How:** Raise in daily standup, add to impediment log, or message directly.
**Expected resolution time:** Same day / next standup

**Examples:**
- Technical blocker (e.g., missing API, unclear requirement)
- Dependency on another team not responding
- Unclear acceptance criteria preventing story completion

---

### Level 2 — Delivery / Process
**Who escalates:** Agile Coach / Scrum Master
**Escalate to:** Project Manager
**How:** Impediment log entry + direct communication (Slack / meeting).
**Expected resolution time:** Within 1–2 business days

**Examples:**
- Cross-team dependency not being resolved
- Resource conflict or capacity gap
- Recurring process dysfunction affecting delivery

---

### Level 3 — Project Management
**Who escalates:** Project Manager
**Escalate to:** Project Sponsor
**How:** Written escalation summary (risk register update + direct notification). Use the [Decision Log](octoacme-decision-log.md) to record the decision request.
**Expected resolution time:** Within 1 sprint / 3–5 business days

**Examples:**
- Budget overrun or additional funding needed
- Scope change requiring executive approval
- Resource request that exceeds PM authority
- Stakeholder conflict at a senior level

---

### Level 4 — Executive
**Who escalates:** Project Sponsor
**Escalate to:** Executive leadership / steering committee
**How:** Executive briefing or escalation email.
**Expected resolution time:** Per leadership cadence or urgency

**Examples:**
- Strategic direction change affecting the project
- Major organizational blocker
- Project continuation / cancellation decision

---

## Escalation Quick Reference Table

| Situation | Start With | Escalate To | Timeline |
|---|---|---|---|
| Technical blocker | Developer | Agile Coach / Scrum Master | Same day |
| Unclear requirement | Developer / QA | Product Owner | Same day |
| Process impediment | Agile Coach / Scrum Master | Project Manager | 1–2 days |
| Cross-team dependency | Project Manager | Project Sponsor (if unresolved) | 1 sprint |
| Budget / scope change | Project Manager | Project Sponsor | 1–3 days |
| Stakeholder conflict | Project Manager | Project Sponsor | As needed |
| Strategic decision | Project Sponsor | Executive leadership | Per cadence |

## Escalation Communication Template

When escalating, include:

```
**Escalation Summary**

Date: YYYY-MM-DD
Raised by: [Name / Role]
Escalating to: [Name / Role]

**Issue / Blocker:**
[Brief description of the problem]

**Impact:**
[Effect on scope, schedule, budget, or quality if not resolved]

**Actions Taken So Far:**
[What has already been tried]

**Decision / Help Needed:**
[What you need from the escalation recipient]

**Deadline for Response:**
[Date by which a response is needed to avoid impact]
```
